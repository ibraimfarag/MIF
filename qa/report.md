# MI CS - QA surface and gates

Generated by `qa/report.dart` from committed files only: no clock, no machine path, no run timing, no hash. That is what lets `test/qa_report_test.dart` compare these two files byte for byte and fail the fast tier - and so CI, which runs the fast tier inside `-Tier full` - when the surface moved and the report did not.

Regenerate deliberately and read the diff: `$env:QA_REPORT_WRITE = "1"; dart run qa\report.dart`.

This is the **registered** surface, not a run. What executed, what was refused and how long it took is in `build/qa-contract.json` (the contract) and `build/pipeline-<tier>.json` (the steps); CI uploads both next to this report.

## What this report does not claim

- It is not a run: it says what is registered and who enforces it, never that today's run passed.
- It names no machine: no user path, no account name, no pid, no hash. The report test fails if one appears.
- Its counts are declarations in committed files, so a test that failed still counts as declared. The gates on *results* are `engine.contract` and the two test steps, not this file.
- Coverage of a registry is not correctness of the product: this says every registered surface has a harness, not that the harness is right.
